# EarMixer

Два созвона одновременно — в **Яндекс Телемосте** и/или **Zoom**: один звучит в **левом** наушнике, другой в **правом**. Любые сочетания: Телемост + Телемост, Zoom + Zoom, Телемост + Zoom.

## Запуск

```bash
npm install
npm start
```

## Как пользоваться

1. У каждой половины окна свой переключатель **Телемост / Zoom**. Вставьте ссылку на встречу (или просто её числовой ID — он трактуется по выбранному сервису) и нажмите «Открыть», либо зайдите во встречу через интерфейс самого сервиса. Сервис определяется и по ссылке: вставили `zoom.us/j/…` — половина сама переключится на Zoom.
   - Zoom открывается в **веб-клиенте** (`/wc/<id>/join`): обычные ссылки `zoom.us/j/…` (в т.ч. корпоративные `company.zoom.us/j/…`, с паролем `?pwd=`) переписываются автоматически, окно «Открыть Zoom Workplace?» не появляется. Имя и пароль встречи веб-клиент спросит сам.
2. Кнопками **Левое / Оба / Правое / 🔇** выберите, в какое ухо идёт звук созвона. «Поменять» в шапке меняет уши местами (Ctrl+Shift+S).
3. **Микрофон** — пускать ли ваш голос в этот созвон. Работает поверх кнопки самого сервиса, так что можно говорить только в одну встречу (Ctrl+1 / Ctrl+2).
4. **Тест** — короткий сигнал в выбранное ухо, чтобы проверить, правильно ли надеты наушники.
5. Индикатор рядом с громкостью показывает, что звук созвона действительно идёт.
6. В шапке можно выбрать устройство вывода и раскладку (оба созвона / только первый / только второй — звук при этом продолжает идти).

Каждый созвон работает в отдельной сессии, поэтому можно войти в два разных аккаунта (Яндекса или Zoom).

## Как это работает

Electron-приложение с двумя встроенными окнами (`WebContentsView`). Перехват звука не зависит от сервиса: до загрузки скриптов страницы в неё внедряется перехватчик (`src/call-preload.js`):

- WebRTC-звук, который сервис проигрывает через `<audio>/<video>` (`srcObject`), забирается в WebAudio, а сам элемент глушится. Для страницы `muted`/`volume` остаются виртуальными, так что кнопки Телемоста и Zoom работают как обычно.
- Всё, что страница подключает к `AudioContext.destination`, перенаправляется в тот же маршрутизатор.
- Перехват распространяется и на вложенные фреймы, включая «пустые» `about:blank`-iframe.
- Маршрутизатор сводит звук в моно и подаёт его только в левый или только в правый канал (`ChannelMerger`).
- Свойство `enabled` у дорожки микрофона тоже виртуальное: реально дорожка включена, только если её разрешают и сервис, и EarMixer.

## Ограничения

- Короткие системные звуки сервисов, проигрываемые по URL (не через WebRTC), могут звучать в обоих ушах.
- Для Zoom используется браузерная версия: часть функций настольного клиента (фоны, некоторые настройки организатора) в ней недоступна, а организатор встречи может запретить вход из браузера.
- Демонстрация экрана на Windows всегда показывает основной монитор.
